# TASK-03 · C：接入首个获准的官方来源

负责人：C。审查：B、A。建议分支：`feat/c-approved-source`。

## 要交付的结果

一个经过准入检查的高校或竞赛主办方公开来源，可以低频发现通知、提取证据、进入待核验状态，管理员核验后发布。

## 从这里开始

- `backend/app/crawlers/base.py`：来源拒绝默认策略与适配器协议。
- `backend/app/crawlers/fixture.py`：现有离线样本适配器。
- `backend/app/services/ingestion.py`：当前仅允许合成数据，不能简单删除限制直接联网。
- `backend/app/models.py`：来源、通知版本与赛事。
- `docs/SOURCE_POLICY.md`：准入表与停止条件。

## 任务范围

- 与团队选择一个条款允许的官方RSS、获准接口或公开静态通知页面，填写来源准入表。
- 实现逐跳域名与路径白名单、内网地址阻断、robots校验、超时和限速；不能仅检查初始URL。
- 首轮只支持一种页面结构；原文、正文哈希、字段证据、解析器版本一并保存。
- 增加有类型校验的规范化输入，真实通知必须进入`pending`，不可调用`approve_demo`自动发布。
- 提供受保护的人工核验/发布接口，记录操作者与证据。
- 同一通知不重复入库；正文变化产生新版本；跨届赛事不自动合并。
- 普通测试只读获准留存样本，联网验证必须显式启用且不进入普通CI。

## 验收

- 来源身份、条款、robots、频率和内容留存依据有记录。
- 401/403、验证码、登录要求、robots禁止均能停止；429遵守退避，不换代理绕过。
- 未核验的真实通知不出现在公开赛事API。
- 能在详情定位截止和资格的原文证据。
- 两次导入同一通知不新增记录；延期变化不被当作重复丢弃。
- 至少10条页面样本覆盖正常、缺失、变更和解析失败；CI不访问真实站点。

若来源不允许，交付拒绝原因并替换来源；不能为了完成任务绕过限制。当前框架不提供任何实际网站授权。
