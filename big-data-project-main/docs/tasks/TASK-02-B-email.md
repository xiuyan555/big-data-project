# TASK-02 · B：实现可追踪的邮件提醒

负责人：B。审查：D、C。建议分支：`feat/b-email-delivery`。

## 要交付的结果

在已有站内通知之外，增加用户明确开启的邮件提醒。邮件每次尝试可追踪，失败不影响站内记录，发送结果未知时不会盲目重发。

## 从这里开始

- `backend/app/services/reminders.py`：提醒重排、到期事件、幂等站内记录。
- `backend/app/worker.py`、`celery_app.py`：Outbox与消费。
- `backend/app/models.py`、`schemas.py`、`routers/me.py`：账户、偏好与接口。
- `backend/tests/test_ingestion_and_reminders.py`：现有边界验证。

## 任务范围

- 增加邮箱、验证状态和显式邮件订阅开关，提交迁移；首轮可使用仅本地生效的验证适配器，标清正式验证尚未接入。
- 增加独立`EmailDelivery`记录，使用稳定业务幂等键，区分`pending / accepted / delivered / failed / unknown`。
- 定义邮件Provider接口，先实现本地测试收件箱适配器；真实服务通过环境变量显式开启。
- 邮件副作用放在独立任务中，不能在持有数据库事务时等待外部服务。
- 发送前复核退订、赛事版本和截止状态。超时结果不明时使用服务商幂等或查询能力；不支持时记录`unknown`。
- 邮件模板使用已核验数据库字段，附官方来源入口；合成数据邮件只能去测试收件箱，并显著标为演示。
- 在后台提供状态查询、失败原因和经检查后的人工重试入口。

## 验收

- 未验证、未开启或已退订邮箱不发送。
- 同一事件重复消费不重复创建邮件投递记录。
- 覆盖暂时失败、永久失败、超时结果不明三种场景。
- 不把`accepted`标成`delivered`或`read`。
- 截止更新后旧版本邮件任务失效。
- 邮件服务不可用时，站内提醒仍正常记录。
- 提供本地测试收件箱截图、必要业务测试和配置说明；不在PR中提交密钥或真实收件人。

改共享模型前通知C与D。本任务不要求向真实用户发送邮件。
