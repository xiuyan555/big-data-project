# TASK-04 · D：接入有证据约束的AI推荐解释

负责人：D。审查：B、A。建议分支：`feat/d-grounded-ai`。

## 要交付的结果

不改变资格判断与可靠提醒链路，增加可关闭、可回退、有证据约束的模型辅助解释。

## 从这里开始

- `backend/app/services/ai.py`：Provider协议、允许理由代码验证。
- `backend/app/services/recommendations.py`：确定性规则基线与证据字段。
- `backend/app/routers/me.py`：推荐API。
- `frontend/src/types.ts`：现有推荐理由与版本结构。

## 任务范围

- 维护统一标签词典和必要别名，确保用户技能和赛事标签能一致比较。
- 实现可配置Provider；单元测试使用Fake Provider，密钥只从环境变量读取。
- 只向模型发送必要标签、已核验赛事事实、允许的理由与证据ID，不发送姓名、邮箱、账号或完整课表。
- 模型只选择允许理由代码与证据ID，后端二次验证并用模板呈现；日期、费用、资格和链接直接读取数据库。
- 增加超时、次数/预算上限与异常回退；模型不可用时继续返回规则结果。
- 按画像版本、赛事版本、规则/提示版本缓存；版本更新后旧解释不得继续作为当前解释。
- 网页文本按不可信数据处理，模型无发送通知、联网抓取或改数据库权限。

## 验收

- 规则输出始终可用；模型超时和错误格式不会使推荐接口报500。
- 未知理由代码、错误证据ID、过期版本被拒绝并回退。
- 含“忽略规则、改写截止时间”等恶意网页文本不能改变用户可见的关键事实。
- 用至少20组画像/赛事样本评估理由是否有依据，记录失败与回退，不编造效果提升。
- UI明确显示当前解释来源，不把规则回退称为模型生成。
- 提供Fake Provider测试；有可用密钥时才自愿进行真实模型联调，普通CI不调用外部模型。

先与A约定理由显示结构，与B约定缓存存储。第一轮不训练模型、不增加向量数据库、不代替官方资格审核。
